# План: React + Vite фронтенд для ducalis-tg (рабочее ядро)

## Контекст (проверено)

Бэкенд готов: миграция v3 + wiring выполнены (коммиты loki `d56116f`, `9f0e0f1`), `go build ./...` зелёный, smoke-тесты (16) проходят. API — JSON-RPC 2.0 через 4 batch-эндпоинта, но рабочее ядро — 3 из них (integrations — заглушка `not implemented`).

**Формат API (подтверждён по exchange-слою):**
- Запрос: `POST /api/v1/{svc}/{svc}Service` c `{"jsonrpc":"2.0","method":"{Svc}Service.{Method}","params":[...],"id":"1"}`
- **Params — позиционный массив**, мапится на именованные поля по порядку: `Login(email, password)` → `params:[email, password]`; `Vote(taskID, userID, weight)` → 3 элемента; `Register(req)` → 1 объект.
- **Ответ — именованный конверт**: `{user, token}` (Login/Register), `{tasks, total}` (List), `{task}` (Vote/SetScores), `{tasks}` (GetRanked).
- Auth: Register/Login возвращают JWT; userID передаётся **явно в params** (не из header). OAuth/RefreshToken — заглушки, не используем.
- DTO: camelCase json-теги (`workspaceId`, `finalScore`, `scores` как map).

## Архитектура

```
web/                          ← React 18 + Vite + TypeScript SPA
  package.json, vite.config.ts, tsconfig.json, index.html
  src/
    api/client.ts             ← JSON-RPC клиент (позиционные params, конверты)
    api/types.ts              ← DTO (зеркало pkg/types, camelCase)
    api/auth.ts / workspaces.ts / tasks.ts   ← типизированные обёртки методов
    store/AuthContext.tsx     ← JWT+user в localStorage, login/logout
    App.tsx                   ← react-router, auth-guard
    pages/LoginPage.tsx       ← tabs: вход / регистрация
    pages/WorkspacesPage.tsx  ← список, создание, конфиг скоринга (RICE/ICE/WSJF/CUSTOM)
    pages/WorkspacePage.tsx   ← задачи: таблица + ranked-режим, фильтры (status/search/sort), создание
    pages/TaskDetailPage.tsx  ← редактирование, оценки по критериям, голосование, estimations, зависимости
    components/               ← Layout, TaskCard, ScoreEditor, VotePanel, RankedTable
    styles.css                ← свой CSS (без UI-фреймворков, минимум deps)
```

**Serving:**
- Dev: `npm run dev` (Vite :5173, proxy `/api/*` → `localhost:8080`).
- Prod: `npm run build` → `web/dist/`, отдаётся **server-public** (`:8080`) — один процесс на всё.

## Правки бэкенда (минимальные, без новых Go-deps)

1. **`cmd/server-public/main.go`**: после transport-роутов — `app.Static("/", "./web/dist")` + SPA-fallback (GET не-`/api` → `index.html`, чтобы работали client-side роуты при обновлении страницы). Static опционален: если `web/dist` нет (сборка без npm) — просто лог и пропуск, `make build` не ломается.
2. **`Dockerfile`**: stage `node:20-alpine` → `npm ci && npm run build`; в runtime — `COPY --from=webbuilder /web/dist /app/web/dist`.
3. **`Makefile`**: цели `web` (build SPA), `web-dev` (Vite dev server); `build` НЕ зависит от web (независимость от node).
4. **`.gitignore`**: `web/node_modules/`, `web/dist/`.

## Функциональность (рабочее ядро)

- **Auth**: регистрация/вход, JWT + user (id, name) в localStorage, redirect на login при 401/ошибке сессии.
- **Workspaces**: список (`List(userID)`), создание, просмотр/правка скоринг-конфига (тип + критерии + formula).
- **Tasks**: список по workspace с фильтрами (status, search, sortBy=finalScore), создание, редактирование, удаление, статусы (backlog/in_progress/done/cancelled), labels.
- **Scoring**: редактор `scores` по критериям из ScoringConfig workspace (RICE: reach/impact/confidence/effort), пересчёт finalScore на сервере (`SetScores`).
- **Voting**: голосовать/снимать голос (свой userID, weight), панель голосов задачи.
- **Estimates**: выставить оценку (value + unit points/hours), список оценок.
- **Ranked view**: переключатель «таблица / приоритеты» — `GetRanked(workspaceID)` с рангами (ядро ценности платформы).
- Интеграции/admin — не включаем (заглушки бэкенда).

## Порядок работ

1. Каркас Vite + TS + роутер + API-клиент (JSON-RPC, конверты) + types.
2. AuthContext + LoginPage (register/login) — проверка живого цикла на запущенном бэкенде.
3. WorkspacesPage (+scoring config).
4. WorkspacePage: список/фильтры/создание задач + ranked-режим.
5. TaskDetailPage: scores/votes/estimates/dependencies.
6. Static в main.go + SPA fallback; Makefile/Dockerfile/.gitignore.
7. Стили, полировка, обработка ошибок (toast/inline).

## Риски/заметки

- Точная схема конвертов сверена по exchange-файлам; при живом тесте поправлю имена полей, если runtime отличается (низкий риск — код сгенерирован из тех же контрактов).
- Node 20+ нужен только для сборки фронтенда; бэкенд и docker-runtime от него не зависят, кроме prod-образа (stage изолярован).
